# Pick Productivity V3

หน้าตา/โครง HTML-CSS-คอมโพเนนต์ของ V2 + ข้อมูลและสูตรจาก Google Sheets ตาม V1 (แยกจากสองโฟลเดอร์เดิม ไม่แก้ต้นฉบับ)

## เปิดดู

ดับเบิลคลิก `START.cmd` (ต้องมี Node.js) หรือรัน `node tools/serve.cjs` แล้วเปิด http://127.0.0.1:8093
ต้องเปิดผ่าน HTTP เพราะตัวคำนวณใช้ Web Worker ไม่รองรับการดับเบิลคลิก index.html แบบ file://

ชุดนี้มี snapshot ข้อมูลจริงพร้อมวันเวลาที่อ่านไว้ เปิดดูได้ทันที เว็บจะอ่านข้อมูลสดจาก Google Sheets แบบ read-only ในเบื้องหลัง ถ้าเชื่อมต่อไม่ได้จะแสดงข้อมูลสำรองพร้อมคำเตือน ไม่เปลี่ยนข้อมูลเป็นศูนย์

## เมนูที่เปิดใช้อยู่ตอนนี้

ถอด 7 หน้าออกชั่วคราวตามที่ผู้ใช้สั่ง (16/09/2569) เพื่อค่อย ๆ นำกลับทีละหน้า

เปิดใช้อยู่ 8 หน้า

| หมวด | เมนู |
|---|---|
| 1 ดูก่อน · ภาพรวม | ภาพรวมวันนี้, แนวโน้มรายเดือน, สรุปผล & Present |
| 2 เจาะลึก & ตรวจข้อมูล | แผนผังโซน, ช่วงเวลา, Training, เกิน 3 เดือน, Not Found & ตรวจข้อมูล |

ถอดออกชั่วคราว: อันดับพนักงาน, ประเภทงาน & โซน, ทะเบียน & รายบุคคล, สังกัด, กะ & BU, รายการต้นทาง, สูตร & แหล่งข้อมูล

มาร์กอัปของทั้ง 7 หน้าเก็บไว้ครบที่ `parked/sections.html` (ไม่ถูกโหลดโดยเว็บ) พร้อมขั้นตอนนำกลับในหัวไฟล์
ตัวเรนเดอร์ของทุกหน้ายังอยู่ครบใน `script.js` / `insights.js` / `v2-views.js` และได้ใส่ null guard ไว้แล้ว
จึงกลับมาทำงานเองเมื่อนำ `<section>` และปุ่มเมนูกลับเข้า `index.html` ไม่ต้องแก้สูตรหรือโค้ดคำนวณ

หน้าภาพรวมยังมีการ์ดกราฟ BU Share, แยกตามสังกัด, สัดส่วนประเภทงาน และเทียบกะอยู่ เพราะเป็นส่วนของผัง overview
ของ V2 เอง ไม่ใช่หน้าที่ถูกถอด ถ้าต้องการให้ตัดการ์ดเหล่านี้ออกจากภาพรวมด้วยให้แจ้งได้

## สิ่งที่ไม่มีในชุดนี้

ไม่มีเมนูสินค้า/UOM/Upload Pick Detail/Workforce Planning เพราะแหล่งนี้ไม่มีข้อมูลระดับ SKU และแผนงานเพียงพอ
การตั้ง Target ที่สืบทอดจาก V1 เป็นมุมมองในเครื่อง ไม่เขียนกลับ Sheet

## หน้าตาอิง V2

โครงที่นำมาใช้ตรงจาก V2 ไม่ใช่การเปลี่ยนสีให้หน้า V1

เปลือกหน้าเว็บ

- Sidebar ขาวกว้าง 250px ติดขอบซ้ายแบบ sticky แบรนด์ไล่สี indigo→teal เมนูจัดกลุ่ม 4 หมวดพร้อมเลขกำกับ (`.nav-group` / `.nav-group-num`), ปุ่มเมนูไล่สี indigo→violet เมื่อเลือก, เมนู Not Found ใช้สีแจ้งเตือนแบบ `.nav-alert`, ท้ายแถบมีปุ่มเปิด Google Sheet / พิมพ์ และ `.sidebadge` แสดงสถานะข้อมูล
- `.pagehead` ชื่อหน้า 26px กับข้อความ “ช่วงข้อมูล: …” ด้านขวา เปลี่ยนตามเมนูและตัวกรองเหมือน `updateDateHeader()` ของ V2
- ค่ากะอ่านจาก Column AG ตามที่ Sheet บันทึก ค่าที่แปลว่าไม่รู้กะ (เซลล์ว่าง, `Not Found`, `Not Found Data`, `#N/A`, `-`) รวมเป็นตัวกรองเดียวชื่อ `Not Found` ผ่าน `V3Metrics.shiftKey()` เพื่อไม่ให้มีปุ่มความหมายซ้ำกัน ส่วนตารางรายการยังแสดงค่าดิบตามต้นทางให้ตรวจย้อนได้
- ตัวกรองเป็นแถบ `.sysbar` ของ V2 เรียงลำดับตามต้นฉบับ: **ระบบ** (`.systog` 3 ปุ่ม ทั้งหมด/PTT/BPS พร้อมไล่สีเฉพาะระบบ) → **กะ** (`.systog.shiftog` ปุ่มสร้างจากค่าจริงในคอลัมน์ AG ใช้อีโมจิ 🅰️/🅱️ เหมือน V2 และ ⚠️ นำหน้ากลุ่ม Not Found) → **🎯 เป้า Target** (`.datebar` ช่องกรอกเลข + หยิบ/ชม. + ปุ่ม ⚙️ ตั้งค่า Target) → **วันที่** (`.datebar` สองช่อง เปลี่ยนแล้วโหลดทันที) → `.preset-range-group` ทั้งหมด / Weekly / Monthly → `.refreshbtn` ↻ รีเฟรช → `.freshtxt` บอกเวลาอ่านข้อมูล
- ช่องกรอก Target ส่งค่าเข้า `updateTargets()` ของ V1 โดยตรง เป้าหมายใหม่จึงมีผลกับทุกการ์ด KPI, เส้น Target ในกราฟ และเกณฑ์เขียว/แดงทันที และบันทึกไว้ในเครื่อง

หน้าภาพรวม — ผังเดียวกับ overview ของ V2 (ไม่ใช่โครงของ V1 อีกแล้ว)

1. แถบแจ้งแหล่งข้อมูลสีเขียวแบบ `source-badge-bar`
2. `.kpis` = การ์ด `.kpi` 5 ใบเรียงแถว (แถบสี 4px ด้านบน ป้าย 12px เทา ตัวเลข 24px): Total Pick, Productivity (AF), Target, พนักงานที่มีผลงาน, Pick to Sort
3. `.card.wide` “แนวโน้มการหยิบ & Productivity” — Chart.js แท่ง+เส้นสองแกน มีปุ่ม `.seg` รายวัน/สัปดาห์/เดือน, แถบเลื่อนเดือน และเส้น Target แบบประ โหมดรายวันกางทั้งเดือนปฏิทินโดยแท่งสีเข้มคือวันที่อยู่ในตัวกรอง เหมือน `drawTrend()` ของ V2
4. `.card.wide` “ปริมาณงานรายชั่วโมง” — Chart.js area line 24 ช่วงเวลาจากคอลัมน์ H–AE
5. แถว 2 คอลัมน์: โดนัท “สัดส่วนระบบ (BPS vs PTT)” พร้อมแผงสถิติซ้าย-ขวาแบบ V2 และแท่งนอน “สัดส่วนตามประเภทงาน (Type Pick Share)”
6. แถว 2 คอลัมน์: โดนัท “BU Share” (คอลัมน์ AJ — ใช้แทนการ์ด Owner Share ของ V2 ที่ต้องใช้ BigQuery) และแท่งสองแกน “แยกตามสังกัด”
7. การ์ดเต็มความกว้าง “เปรียบเทียบผลงานแยกกะ” — แท่ง Total Pick + เส้น Productivity ตามคอลัมน์ AG

หน้าอันดับพนักงานมีการ์ดกราฟ `#picker` แบบ V2 (แท่งนอน + `.systog` Top 12/20/50 · เขียว = ถึง Target, แดง = ยังไม่ถึง) อยู่เหนือกระดานจัดอันดับเดิม

ส่วนที่เหลือของคอมโพเนนต์

- กราฟทั้งหมดใช้ Chart.js 4.4.1 + chartjs-plugin-datalabels 2.2.0 จาก cdnjs เวอร์ชันเดียวกับ V2 ตั้ง `Chart.defaults.font.family = 'Prompt'` และ `Chart.defaults.color = '#64748b'` ตาม V2 พร้อมพาเลต indigo / teal / violet / amber / rose / sky
- ตารางใช้ `.affiliation-table` + `.affiliation-table-wrap` ของ V2 (หัวตารางเทา 12px ไม่พิมพ์ใหญ่, เส้นคั่นบาง, hover อ่อน, เลื่อนแนวนอนในกรอบ)
- แผนผังโซนใช้ `.heat` + `.tile` ของ V2 และ badge/pill ใช้ `.pill` / `.badge-status`
- หน้าวิเคราะห์เชิงลึกที่สืบทอดจาก V1 (Training, เกิน 3 เดือน, สังกัด, ประเภทงาน & โซน, กะ & BU, Present, ทะเบียน, รายการต้นทาง, Not Found) ยังคงเนื้อหาเดิมครบ แต่จัดหน้าตาให้เข้าชุด V2 ตามที่ตกลงไว้
- จอแคบใช้กฎของ V2: ที่ ≤900px Sidebar กลายเป็นแถบเลื่อนแนวนอนด้านบน ตัวกรองเรียงเต็มความกว้าง KPI เหลือ 2 คอลัมน์ การ์ด/กราฟเหลือคอลัมน์เดียว และป้ายแกนกราฟบางลงไม่ให้ทับกัน

## ไฟล์สำคัญ

หน้าตา (โครง/เลย์เอาต์/คอมโพเนนต์ยึดของ V2)

- `index.html`: โครงหน้าแบบ V2 — `.layout > .sidebar + .content`, Sidebar จัดกลุ่มเมนู 4 หมวดพร้อมหมายเลข, `.pagehead` (ชื่อหน้า + ช่วงข้อมูล), แถบตัวกรอง `.sysbar`, หน้าภาพรวมเป็น `.kpis` + กริดการ์ดกราฟตาม overview ของ V2 และ `section.page/.tab-panel` ต่อเมนู
- `v2-base.css`: CSS ของ V2 คัดมาตามต้นฉบับจาก `<style>` ใน `Pick Productivity_V2/index.html` บวกสไตล์ `.sysbar/.systog/.datebar/.datepreset/.refreshbtn` ที่ V2 สร้างจาก `ensureStyles()` ใน app.js — ไม่แก้ค่าใด ๆ
- `v2-theme.css`: สะพานให้คอมโพเนนต์ที่สืบทอดจาก V1 (KPI, การ์ด, ตาราง, heat tile, badge, ปุ่ม, ตัวกรองย่อย) ใช้ภาษาการออกแบบเดียวกับ V2 รวม responsive 1200/900 px และ print
- `v2-shell.js`: สลับเมนู, เปลี่ยนชื่อหน้าบน `.pagehead`, แถบ “ช่วงข้อมูล …” และผูกปุ่ม `.systog` เลือกระบบเข้ากับตัวกรองเดิม — ไม่คำนวณตัวเลข
- `v2-views.js`: วาดกราฟชุดของ V2 ด้วย Chart.js (แนวโน้ม, รายชั่วโมง, โดนัทระบบ, ประเภทงาน, BU, สังกัด, กะ, อันดับพนักงาน) โดยรวมยอดผ่าน `V3Metrics` ซึ่งเป็นสูตร V1 ทั้งหมด ไม่คำนวณสูตรใหม่และไม่แตะ `v1-engine.js`
- `styles.css`: CSS เดิมของ V1 โหลดเป็นชั้นล่างสุดเพื่อคงเรขาคณิตของคอมโพเนนต์เชิงลึก (Training, Zone, Picker board) แล้วให้สองไฟล์ข้างบนทับสี/ตัวอักษร/ระยะให้เป็น V2 (ลำดับโหลด: styles.css → v2-base.css → v2-theme.css)
- `parked/sections.html`: มาร์กอัปของหน้าที่ถอดออกชั่วคราว เก็บไว้เพื่อนำกลับทีละหน้า เว็บไม่โหลดไฟล์นี้

ข้อมูลและสูตร (ยึดของ V1 ทั้งหมด)

- `v1-engine.js`: ตัวคำนวณ V1 ภายใน read-only adapter ทำงานใน Worker
- `script.js`: การแสดงผลและการรวมข้อมูล V1
- `source.js`: อ่าน CSV export ครบทุกแถว (ไม่ใช้ gviz ที่อาจตัดแถวตาม filter และทำรหัสผสมตัวเลข/ตัวอักษรหาย)
- `data-worker.js` / `data-client.js`: โหลด snapshot, แคชแยก V3, อ่านสดและคำนวณเบื้องหลัง
- `metrics.js` / `insights.js`: การเจาะลึกจากรายการต้นทาง
- `data/snapshot.json`: ข้อมูลจริง ณ เวลาที่ระบุในไฟล์ รวมชื่อ/รหัสพนักงาน ใช้สำหรับเปิดทดลองและสำรอง

ไม่มีการแก้ไฟล์ใน `Pick Productivity` (V1) และ `Pick Productivity_V2` จากงานนี้ — ไฟล์ของ V2 ถูกอ่านเท่านั้น

## Deploy ภายหลัง

ยังไม่ได้สร้าง Git repository หรือ push V3 ตามที่ผู้ใช้จะสร้างปลายทางใหม่หลังทดลองผ่าน สามารถใช้ static hosting เช่น GitHub Pages; วางไฟล์ให้ครบรวม data/snapshot.json ไม่มีขั้นตอน Deploy Apps Script และไม่ต้อง Run SQL ให้ Google Sheets แชร์แบบที่ผู้ชมมีสิทธิ์อ่าน export ได้ หากอ่านสดไม่ได้เว็บจะแสดง snapshot พร้อมสถานะอัปเดตไม่สำเร็จ

V1 และ V2 เดิม รวมทั้งข้อมูล BigQuery ไม่ได้ถูกแก้ไขหรือลบจากงานนี้
