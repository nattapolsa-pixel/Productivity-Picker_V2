## ไม่ถึงเป้า (แยกตามโซน)

ลอกองค์ประกอบมาจากหน้า `belowtarget` ของ V2 (`app.js` renderBelowTargetPage 5936-6033 และ drawBelowTargetChart 6035-6104)
เมนูอยู่กลุ่ม 2 ใช้ `data-page="below-target"` คลาส `nav-alert` เหมือน V2 · โค้ดอยู่ใน `insights.js` ฟังก์ชัน `belowTargetPage()`

องค์ประกอบตามลำดับเหมือน V2

1. การ์ดสรุป 5 ใบ (`.zone-summary` / `.zone-stat`) — ไม่ถึงเป้ากี่คน · สัดส่วน % · ช่องว่างเฉลี่ย · โซนที่ต้องดูก่อน · โซนที่มีคนไม่ถึงเป้า n/m
2. กราฟแท่งซ้อนต่อโซน แดง = ไม่ถึงเป้า (คน) เขียว = ถึงเป้า (คน) เรียงโซนที่แย่สุดขึ้นก่อน สูงสุด 20 โซน
3. โน้ตเกณฑ์การนับ
4. ตารางโซน — ไม่ถึงเป้ากี่คน / คนทั้งหมด / สัดส่วน / ค่าเฉลี่ยโซน / Target โซน / ช่องว่างเฉลี่ย / Total Pick
5. ตารางรายคนที่ไม่ถึงเป้า เรียงคนที่ห่างจากเป้ามากที่สุดขึ้นก่อน

กฎการนับ (เป็นของ V1 ทั้งหมด)

- ค่าเฉลี่ยรายคน = ผลรวมคอลัมน์ AF เฉพาะค่า > 0 ÷ จำนวนแถวนั้น (`v1-engine.js` finalizePickerRows_ 1752) ไม่เฉลี่ยค่าเฉลี่ยซ้ำ
- **ไม่ถึงเป้า = ค่าเฉลี่ย < Target ของโซน** เท่ากับเป้านับว่าผ่าน (`v1-engine.js` finalizeBucket_ 2111)
- คนที่ไม่มีแถวเข้าเฉลี่ย (AF > 0) ไม่ถูกตัดสิน ตามที่ V1 ทิ้งคนที่ `count = 0`
- Target ของโซนมาจาก `getZoneTarget(zoneKey, groupKey)` คือดูค่าที่ตั้งรายโซนก่อน ถ้าไม่ได้ตั้งจึงใช้ Target ตามประเภทงาน
  แก้ได้ที่ปุ่ม **⚙️ ตั้งค่า Target** (มีช่องครบทั้ง 17 โซน)
- คนหนึ่งคนนับครั้งเดียว ยึด **โซนหลัก** = โซนที่มีแถวเข้าเฉลี่ยมากที่สุด เหมือนที่ V2 เทียบรายคนกับโซนหลัก
  จำนวนคนรายโซนจึงบวกกันได้เท่ากับยอดรวมพอดี ไม่นับซ้ำ
- แถวที่คอลัมน์ AH ไม่ตรงกฎโซนของ V1 ไปอยู่กอง **Not Found** ซึ่งใช้ Target รวม ไม่ใช่โซนจริง
  จึงไม่ถูกเลือกเป็น "โซนที่ต้องดูก่อน" และมีข้อความเตือนไว้ในโน้ต

## เรียงข้อมูลในตาราง

ทุกตารางที่ใช้ `V3Shared.table()` กดหัวคอลัมน์เพื่อเรียงได้

- กดครั้งแรก **มาก → น้อย** ครั้งที่สองน้อย → มาก ครั้งที่สามกลับลำดับตั้งต้นของหน้านั้น
  (ต้องมีสถานะที่สาม เพราะบางตารางจัดลำดับมาก่อนแล้ว เช่นการ์ด Not Found ดันคนที่ออกแล้วไปท้าย)
- ค่าว่างไปท้ายรายการเสมอ คอลัมน์ที่แปลง `null` เป็น 0 เพื่อแสดงผล ให้ใส่ `sortValue` กำกับไว้
- เรียงข้อความไทยด้วย `localeCompare(…, 'th')` · กดด้วย Enter/Space ได้ และตั้ง `aria-sort` ให้ screen reader
- Export CSV ออกตามลำดับที่เห็นบนจอ

## พนักงานใหม่ / พนักงานเก่า

เกณฑ์อายุงานใช้กฎเดียวกับ V1 (`buildTenuredPickerBenchmark` ใน `script.js`)

- `anchor` = วันล่าสุดที่มีข้อมูล · `cutoff` = anchor ลบ **90 วัน** (ไม่ใช่ 3 เดือนปฏิทิน)
- **พนักงานใหม่** = วันเริ่มงานหลัง cutoff · **พนักงานเก่า** = วันเริ่มงานก่อนหรือเท่ากับ cutoff
- วันเริ่มงานยึด `Update name` คอลัมน์ H เหมือน V1 ก่อน แล้วใช้ `2ND` คอลัมน์ G เป็นตัวสำรอง
  (V1 ไม่ได้อ่านคอลัมน์นี้ ส่วนนี้เพิ่มเข้ามาเพื่อให้ครอบคลุมคนมากขึ้น) ถ้าไม่มีทั้งสองที่จึงใช้วันแรกที่พบผลงาน
  ใน Results Master เหมือน `firstSeen` ของ V1 ทำให้ทุกคนที่มีผลงานถูกจัดกลุ่มได้ ไม่มีใครตกกลุ่ม

แต่ละหน้ามี KPI 5 การ์ด, กราฟ Chart.js, การ์ดสรุป "สิ่งที่ควรทำต่อ" และตารางรายคนที่ค้นหา/Export CSV ได้

- **พนักงานใหม่**: เส้นการพัฒนา (Learning Curve) ตามสัปดาห์ที่นับจากวันแรกที่มีผลงาน เทียบ Target
  และค่าเฉลี่ยของพนักงานเก่า · กราฟ Productivity รายคน · คอลัมน์ "สัปดาห์แรก → ล่าสุด" บอกว่าดีขึ้นเท่าไร
- **พนักงานเก่า**: แนวโน้มรายเดือนของกลุ่ม (แท่ง Total Pick + เส้น Productivity + เส้น Target) ·
  กราฟ 10 อันดับสูงสุดและ 10 อันดับต่ำสุด · คอลัมน์ "เทียบเดือนก่อน" บอกว่าเดือนล่าสุดดีขึ้นหรือแย่ลง

ทุกกลุ่มยังใช้สูตร V1: Total Pick = ผลรวมคอลัมน์ E · Productivity = ผลรวมคอลัมน์ AF ของแถวที่ AF > 0
หารด้วยจำนวนแถวนั้น รวม sum/count ครั้งเดียวทั้งรายคน รายสัปดาห์ และรายเดือน

## รหัสที่ต้องตามข้อมูล (Not Found)

ทั้งหน้าพนักงานใหม่และพนักงานเก่ามีการ์ด **⚠️ รหัสที่ต้องตามข้อมูล** ดึงคนที่ยังมีช่องว่างหรือ Not Found ออกมาแยก
พร้อมบอกว่าต้องไปเติมที่ชีตไหน คอลัมน์ไหน

| สิ่งที่ขาด | ต้องไปเติมที่ |
|---|---|
| ไม่มีใน 2ND | เพิ่มแถวในชีต `2ND` (B รหัส, C ชื่อ) |
| ไม่มีชื่อ | `2ND` คอลัมน์ C ชื่อ-นามสกุล |
| ไม่มีวันเริ่มงาน | `Update name` คอลัมน์ H (หรือ `2ND` คอลัมน์ G) |
| กะ Not Found | `Results Master` คอลัมน์ AG |
| สังกัดว่าง | `Results Master` คอลัมน์ AI |
| BU ว่าง | `Results Master` คอลัมน์ AJ |
| Type Pick ว่าง | `Results Master` คอลัมน์ AK |
| Zone ว่าง | `Results Master` คอลัมน์ AH (Position) |

- การ์ดบอกจำนวนคนและ **Total Pick ที่กระทบ** เพื่อจัดลำดับว่าควรตามใครก่อน
- แถบ pill ด้านบนสรุปว่าขาดอะไรกี่คน ชี้เมาส์ค้างเพื่อดูว่าต้องไปเติมที่ไหน
- ใช้ปุ่ม **ซ่อนคนที่ออกแล้ว** ร่วมกับการ์ดนี้ได้ เพราะคนที่ลาออกแล้วไม่จำเป็นต้องตามข้อมูล
- กด **Export CSV** เพื่อเอารายการไปไล่แก้ใน Sheet ได้เลย
- ผลงานของคนเหล่านี้ **ไม่ถูกตัดออกจากยอดใด ๆ** ตามกฎ V1 แต่ KPI ที่ต้องใช้ข้อมูลนั้นจะเชื่อถือไม่ได้

V3 อ่านข้อมูลอย่างเดียว จึงกรอกข้อมูลกลับเข้า Sheet จากหน้าเว็บไม่ได้ ใช้ Export CSV แทน

## หน้าต่างกรอกข้อมูล (เก็บไว้ในเครื่อง ยังไม่ส่งเข้า Sheet)

ในการ์ด "รหัสที่ต้องตามข้อมูล" (หน้าพนักงานใหม่/พนักงานเก่า) และการ์ด "รหัสพนักงานที่ยังไม่มีทะเบียน"
(หน้า Not Found & ตรวจข้อมูล) มีปุ่ม **✏️ เติมข้อมูล** ต่อแถว เปิดฟอร์มกรอกในหน้าเดียวกันได้เลย

ตามที่ผู้ใช้สั่งไว้ **ฟอร์มนี้ยังไม่ยิงข้อมูลออกไปที่ Google Sheet** ไม่มีการเรียก Apps Script
และไม่มีกล่องตั้งค่า URL/โทเคนในหน้าเว็บ ที่กรอกจะเก็บใน `localStorage` ของเครื่องนั้น
แล้วกด **Export CSV ที่กรอกไว้** เอาไปวางในชีตเอง

### สถานะการจ้าง — ตอบคำถาม "ถ้าลาออกไปแล้วจะให้กรอกตรงไหน"

ในฟอร์มมีปุ่มสองตัวเลือกอยู่บนสุด ปลายทางต่างกัน

| เลือก | ช่องที่ให้กรอก | ปลายทางที่ต้องไปวาง |
|---|---|---|
| ยังทำงานอยู่ | 10 ช่อง (ชื่อ, ชื่อเล่น, สังกัด, หน้าที่, วันเริ่มงาน, Status Work, Zone, Pick Type, BU, กะ) | ชีต **2ND** คอลัมน์ C–M |
| ⛔ ลาออกแล้ว | 3 ช่อง (ชื่อ, วันที่พ้นสภาพ, หมายเหตุ) | ชีต **Resigned** คอลัมน์ A รหัส · B ชื่อ · H วันพ้นสภาพ |

- กด ⛔ ลาออกแล้ว แล้วบันทึก → แถวนั้นขึ้น Remark **สีส้ม "⛔ ออกแล้ว · กรอกในเว็บ"** ทันที
  แยกจากสีแดงที่หมายถึง "ยืนยันแล้วจากชีต Resigned" และถูกซ่อนตามปุ่ม **ซ่อนคนที่ออกแล้ว** เหมือนกัน
- คนที่กรอกในเว็บว่าออกแล้วจะ **ค้างอยู่ในการ์ดต่อ** จนกว่าจะเอาไปใส่ในชีต Resigned จริง
  (นับแยกไว้ที่ป้าย "กรอกในเว็บรอใส่ใน Sheet") เพื่อไม่ให้ลืมว่างานยังไม่จบ
- วันที่พิมพ์ได้ทั้ง `31/08/2026`, `31/08/2569` (พ.ศ.) และ `2026-08-31` · อ่านไม่ออกจะเตือนไม่ให้บันทึกมั่ว
  · เว้นว่างได้ถ้าไม่รู้วัน จะขึ้นว่า "ไม่ทราบวันที่"
- CSV ส่งออก **วันที่พ้นสภาพเป็น ปี ค.ศ. แบบ `yyyy-mm-dd`** เพื่อให้วางลงชีตแล้วไม่เพี้ยนตามรูปแบบวันที่
  และมีคอลัมน์ "ปลายทางที่ต้องไปกรอก" บอกชีต/คอลัมน์ของทุกแถว
- สลับปุ่มไปมาไม่ทำให้ที่กรอกไว้หาย ค่าของอีกสถานะยังถูกเก็บไว้และติดไปใน CSV ด้วย
- คนที่อยู่ในชีต Resigned อยู่แล้ว ฟอร์มจะตั้งค่าเป็น "ลาออกแล้ว" ให้และขอแค่ชื่อ
  ถ้าคนนั้นกลับมาทำงาน ต้องแก้ที่ชีต Resigned ก่อน เพราะชีตเป็นแหล่งจริง หน้าเว็บทับไม่ได้ (มีข้อความบอกไว้ในฟอร์ม)

- ของที่จะหายเมื่อลบ: trigger `syncPickMastersDaily` และ `warmDashboardCache`
  (sync ลง CacheService/PropertiesService ไม่ใช่ลงชีต) และ **shared targets / excluded zones ของ V2**
  ที่เก็บใน `PropertiesService` ซึ่งกู้ไม่ได้
- ยังไม่ได้ยืนยัน: โปรเจกต์ที่ deploy อยู่จริงอาจมีโค้ด/trigger ไม่ตรงกับไฟล์ในเครื่อง
  ก่อนลบให้เปิด Apps Script ของชีตดู **Triggers** และ **Manage deployments** อีกครั้ง
- แนะนำลำดับตอนจะลบ: ลบ trigger → Archive deployment (URL ตายแต่โค้ดอยู่) → รอสองสามสัปดาห์ → ลบจริง
- `apps-script-roster-write.gs` ของ V3 ควร Deploy เป็น **โปรเจกต์แยก** ไม่วางทับของเดิม
  เพื่อให้ลบของเดิมได้อิสระ

## Deploy ภายหลัง

ยังไม่ได้สร้าง Git repository หรือ push V3 ตามที่ผู้ใช้จะสร้างปลายทางใหม่หลังทดลองผ่าน สามารถใช้ static hosting เช่น GitHub Pages; วางไฟล์ให้ครบรวม data/snapshot.json ไม่มีขั้นตอน Deploy Apps Script และไม่ต้อง Run SQL ให้ Google Sheets แชร์แบบที่ผู้ชมมีสิทธิ์อ่าน export ได้ หากอ่านสดไม่ได้เว็บจะแสดง snapshot พร้อมสถานะอัปเดตไม่สำเร็จ

V1 และ V2 เดิม รวมทั้งข้อมูล BigQuery ไม่ได้ถูกแก้ไขหรือลบจากงานนี้
